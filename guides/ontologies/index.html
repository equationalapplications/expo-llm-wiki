Ontologies

Read Knowledge graph & ontology first for the background. This page covers the practical side.

Seed at construction time

Section titled “Seed at construction time”

A seed is written to the database the first time the entity’s ontology is resolved inside a transaction (on ingest or heal). Until then, getOntologyManifest() still reports it.

Read and set at runtime

Section titled “Read and set at runtime”

Pick one seeding route per entity

ifAbsent checks for a persisted row, not for a configured seed. An entity seeded only through seedManifests has no row yet, so ifAbsent will overwrite the seed. Seed each entity through config or through the API, not both.

validateManifest(manifest) is exported if you want to check a manifest before saving it.

What the model returns

Section titled “What the model returns”

In strict and emergent modes the extraction JSON may include a type and inline edges:

  • okf_type is matched case-insensitively and stored with the manifest’s casing.
  • Edges are resolved by target_title within the same transaction.
  • An invalid okf_type stores the fact untyped and drops its edges. An invalid individual edge is dropped (and reported as an edge_dropped diagnostic).
  • In emergent mode the model may add ontology_updates.node_types and edge_types. These are append-only and deduplicated by type. A malformed parent_type in a proposal is dropped, not thrown.

Inheritance

Section titled “Inheritance”

Edges declared on creativework now also match design_spec. When several edges could match a target, the exact type wins over the parent. Validation rejects any of the following:

Problem Error message
Unknown parent Parent type not found: <slug>
Self-parent Self-parent: <type>
Two or more levels Parent chain too deep: a → b → c
Blank or non-string parent_type Ontology parent_type must be a non-empty string when present

How it behaves in detail:

  • One level, checked everywhere. The manifest is validated whenever it’s saved and whenever it’s read. setOntologyManifest rejects a chain up front. The depth check also catches 2-cycles (a → b → a).
  • Absent is fine, blank isn’t. Leaving out parent_type means “no parent”. A key that is present must be a non-empty string.
  • Parents are real types. A fact can be classified as the bare parent (creativework). There’s no abstract flag. To steer the model toward the children, say so in the parent’s description.
  • Matching works on both ends, one hop. A child satisfies an edge declared on its parent as either the source or the target. Matching never walks further than one level.
  • The trade-off. An edge declared to creativework admits every child of creativework, and there’s no way to say “the parent only”. A type that needs exact-only targets must not have children.
  • Emergent mode. The model may propose parent_type in ontology_updates. Those proposals are treated as untrusted: an invalid parent_type is dropped rather than failing the ingest. To change an existing type’s parent, call setOntologyManifest.
  • No migration needed. parent_type is optional, and manifests without it validate exactly as before.

The full design is in the ontology parent field spec.

Backfill untyped facts

Section titled “Backfill untyped facts”

Facts that bypassed the librarian (imports, or data from before ontologies) have no type and no edges. runOntologyBackfill() types them in place:

  • Stop when a pass doesn’t lower remaining. A fact whose provider call keeps throwing (a call_error, or a thrown classify) gets no cooldown stamp and stays eligible, so a bare while (remaining > 0) loop can spin on it forever. The guard above stops on no progress; the next trigger retries.
  • You own the trigger. Running it after each sync or import is a good default. It’s safe to swallow a WikiBusyError, since the next run retries.
  • It only adds. It never creates, deletes, or rewrites facts, never overwrites an existing type, and never changes updated_at.
  • Cost: a single SELECT when there’s nothing to do. Otherwise it scans up to 25 facts per run (batchSize), in sub-batches sized from maxOutputTokens. Sub-batches that fail are halved and retried.
  • Facts it can’t classify are retried after 7 days (reported as deferred).
  • Customize the prompt with options.promptOverride or config.prompts.ontologyBackfillSystemPrompt.

Classifier mode

Section titled “Classifier mode”

A non-generative classifier can do the typing at lower cost. Add classify to the provider and opt in:

  • Each untyped fact gets one choice question over the manifest’s node types.
  • Answers below classifyMinConfidence stay untyped.
  • Classifier mode proposes no edges. Use classifier: 'llm' when you want edges.
  • More than 255 node types, or no classify function, means the generative path is used.

Curated Thoughts uses this with a Jev classifier on Cloudflare Workers AI (typesafe/jev), behind its Type untyped facts button.

classify receives { state, questions }, where each question is choice, binary, or score. It returns { answers }, which the engine validates as untrusted input: off-list choices and out-of-range probabilities count toward failedValidation, and a classify call that throws counts toward skipped and is retried on the next pass. Answers below classifyMinConfidence are retried after the cooldown.
