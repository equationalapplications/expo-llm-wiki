## 1. Problem

Three core-llm-tools declarations used a `wiki_<verb>_<noun>` scheme: `wiki_traverse_graph`, `wiki_get_ontology` and `wiki_get_instructions`. SynapseTree's MCP surface names its tools `<resource>_<verb>`. Renaming in place would change the names an unchanged host's model emits, and the host's function-call `switch` would stop matching. That is the breaking form, and the ruling reserves it for the removal major.

## 2. Change (as ruled)

1. **Canonical declarations added** as new exports: `graphTraverseManifest` (`graph_traverse`), `ontologyGetManifest` (`ontology_get`) and `instructionsGetManifest` (`instructions_get`).
2. **Legacy declarations kept** within 7.x. `wikiTraverseGraphManifest`, `wikiGetOntologyManifest` and `wikiGetInstructionsManifest` are each derived from the canonical twin by name substitution only (`renamed()` in `src/legacy.ts`), so parameters and descriptions cannot drift. Each one is `@deprecated` in JSDoc and names its replacement. The derivation deep-copies, so twins share no nested object.
3. **Migration helpers.** `LEGACY_TOOL_NAMES` is a frozen old-to-new map. `canonicalToolName(name)` returns the canonical name for a legacy name and any other name unchanged. It logs one deprecation warning per process, the first time it maps a legacy name. The flag lives on `globalThis` under a `Symbol.for` key, so the CJS and ESM builds share it. The helpers are deliberately *not* `@deprecated`: they are the migration path the docs prescribe.
4. **Byte-identity within 7.x.** A host that changes nothing sends exactly the 7.15.2 declarations. A fixture captured from the published 7.15.2 enforces this.
5. **Never both.** The docs tell hosts never to send the legacy and the canonical declaration for one operation to the same model.
6. **Changelog.** `.releaserc.json` gives the release-notes generator a `deprecate` → "Deprecated" section (the preset defaults restated, plus that one type; commit-analyzer is untouched, so the type never bumps). A `deprecate(core-llm-tools):` commit in this PR lists the three legacy names there. `CHANGELOG.md` stays generated by semantic-release.
7. **Docs.** The README, the docs site (package page, Gemini recipe, prompts guide, security page), the `packages/core` JSDoc that names the tool, and §6 of `docs/synapsetree-integration.md` all use the canonical names.

## 3. Removal (#324)

The legacy exports, `LEGACY_TOOL_NAMES` and `canonicalToolName` are removed at the next major of core-llm-tools, at least one minor release after 7.17.0. The `graph.ts` `sourceId` description wording (kept now for byte-identity, N1) is revisited in the same change.

## 4. Tests

`packages/core-llm-tools/__tests__/legacy.test.ts` covers:

- the map: exactly the three pairs, frozen;
- continued export and name-only derivation of each legacy declaration;
- no shared nested objects between twins;
- byte-identity against the 7.15.2 fixture;
- no overlap between the canonical and legacy name sets;
- mapping, and pass-through for canonical, unknown and prototype-key names;
- a single warning per process, even across two module instances.

The release-notes rendering was checked by running the installed plugins on sample commits. `deprecate` alone gives no release; with the `feat` it gives a minor and a "Deprecated" section listing the three names.
