# Native GraphRAG Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the portable Rust crate `graphrag-core` proving one read-only operation — `traverse_graph_neighborhood`, the native equivalent of core 7.1.3's `WikiMemory.traverseGraph` — with parity fixtures, variable-limit-safe reads, the SQLite host contract, and the predeclared benchmark scaffolding.

**Architecture:** A greenfield in-repo crate at `crates/graphrag-core` with no Tauri/Node/RN dependency. Traversal is a breadth-first Rust walk (shortest-depth, per-node visited set) over rusqlite reads, followed by chunked induced-edge fetch and chunked ordered hydration — not a recursive CTE. Two entry paths (borrowed `Connection` = engine-owned deferred read snapshot; borrowed `Transaction` = host-owned, never committed) implement REQ-SQL-01. Compatibility fixtures are JSON files generated once from the pinned TS baseline's real-SQL tests and asserted from Rust.

**Tech Stack:** Rust stable (1.96 toolchain on dev box), `rusqlite` (bundled SQLite; pin the version recorded at scaffold time in `Cargo.lock`), `serde`/`serde_json`, `thiserror`. Fixture generator runs under the repo's existing vitest 4.1.11 toolchain — no new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-09-17-native-graphrag-vertical-slice-design.md` (rev 5, merged via PR 190 at `09212f8`). Baseline: `453e5c8` (core 7.1.3).

## Global Constraints

- **REQ-SLICE-01:** Native equivalent of `WikiMemory.traverseGraph(entityId, options)`; required `sourceId`; optional `maxDepth`, `direction`, `edgeTypes`, `maxTraversalNodes`, `minTraversalConfidence`, `excludeSourceTypes`. Entity scope (`entity_id = ?`) binds in **every** SQL statement (walk neighbor join, induced-edge fetch, hydration) — it is a disclosure boundary.
- **Depth:** default 1; clamp the real-valued bound `d = max(1, min(maxDepth ?? 1, 3))` **without rounding**; discovery at integer depth `k` happens iff `k ≤ ceil(d) − 1` is generated by expanding frontiers while `k − 1 < d` (so `d = 1.5` reaches depth 2; `d = 1` reaches depth 1). Reject non-finite `maxDepth` with `invalid_argument` (declared difference).
- **Anchor:** retained even when isolated or failing confidence/source-type gates; **anchor node first** is a public ordering guarantee. Missing/deleted/foreign-entity root → empty result (well-formed ID only).
- **Discovery gates (discovered nodes only):** confidence rank `tentative(0) < inferred(1) < certain(2)`, unknown stored confidence ranks −1; `source_type NOT IN (exclusions)`; `edgeTypes` allow-list (`undefined`/absent = no filter, `[]` = match nothing, opaque untrimmed strings).
- **Ordering/cap:** unique nodes ordered depth ASC, then `updated_at` DESC, then capped to `maxTraversalNodes` (default 20; includes root). Ties beyond that are unspecified — native uses a documented stable tiebreak (`id` ASC). Cap is a result limit, not a traversal-work limit.
- **Edges:** induced subgraph on selected nodes within the entity; the final edge query does **not** reapply direction/`edgeTypes`. Edge identity = full row (id, entity_id, source_id, target_id, edge_type); dedupe by that identity. Edges have no ordering guarantee — native emits a stable order.
- **Hydration:** full `WikiFact` DTO in selected-node order; missing facts omitted; edges with un-hydrated endpoints dropped; one clock sample per row at mapping time, sequential. Injectable clock in tests.
- **Baseline defect (declared):** comma-delimiter visited-string can suppress IDs containing the delimiter — native uses collision-free per-node identity tracking. Fixtures record separate expectations (category b).
- **REQ-INPUT-01:** structured `invalid_argument` errors naming the field, before any traversal SQL runs. `maxTraversalNodes`: decode JSON numbers as f64 (never i64), require finite, `>= 1`, floor; floor within signed 64-bit range is accepted, otherwise `unsupported_limit` (never wrap/clamp). Invalid per-call value falls back to the sanitized config default; both invalid → 20. `excludeSourceTypes` values are opaque text (no enum check). Unknown option keys ignored. Empty/`null` optionals = absent; `edgeTypes: null` = absent.
- **REQ-SCALE-01:** induced-edge fetch must not bind one variable per selected node in a single query. Chunk **source** IDs (500 per chunk, matching `EntryRepository.chunkSize`), keep targets in the complete selected set. `edgeTypes`/`excludeSourceTypes` bind in bounded groups preserving union/exclusion semantics. Hydration chunks = 500 IDs.
- **REQ-SQL-01:** two distinct entry paths; never guess transaction ownership; the engine never commits/rolls back a caller-owned transaction; no transaction spans IPC requests.
- **REQ-SQL-04:** read-only slice — no migrations, no schema creation. Validate required tables/columns and `${prefix}meta` key `schema_version` = **11** (core 7.1.3 `CURRENT_SCHEMA_VERSION`); explicit failure leaves the DB unchanged. Table prefix from trusted host config, default `llm_wiki_`, never per-request.
- **REQ-COMPAT-01:** no TS rewrite, no mutation engine, no production switch; the pinned TS baseline stays byte-identical except for the fixture-generator test file (additive).
- **REQ-DOC-01:** this plan, code, and tests travel on the same branch/PR as the spec. Merge convention: regular merge commit (never squash).
- **REQ-SQL-03 (desktop lifecycle subset, in scope):** `lifecycle_tests.rs` covers the non-mobile bullets that apply to the engine itself — snapshot consistency across walk/hydration (synchronization hooks, no timing sleeps), no observation of uncommitted host writes, caller-owned transaction survives engine errors, and bounded busy handling with surfaced errors. The mobile-binding bullets (on-device write-await, boundary probe through the binding, iOS/Android evidence) are adoption-gate work.
- Out of scope for this PR (gates, not slice): mobile binding evidence (REQ-SQL-02 and REQ-SQL-03's mobile portions on-device), CT renderer boundary proof (REQ-SLICE-03.2), clanker proof (REQ-SLICE-03.3), benchmark *execution/publication* (REQ-PERF-01 run). This PR ships the crate, the headless proof (REQ-SLICE-03.1 via `cargo test`), fixtures, CI, and the benchmark harness scaffold.

```rust
fn sanitize_cap(v: f64) -> Option<f64> {
    if v.is_finite() && v >= 1.0 { Some(v.floor()) } else { None }
}
fn resolve_cap(call: Option<f64>, config: Option<f64>) -> Result<u64, GraphragError> {
    let eff = sanitize_cap(call.unwrap_or(f64::NAN))
        .or_else(|| sanitize_cap(config.unwrap_or(f64::NaN)))
        .unwrap_or(20.0);
    if eff > i64::MAX as f64 {
        Err(GraphragError::UnsupportedLimit { field: "maxTraversalNodes".into(), value: eff })
    } else { Ok(eff as u64) }
}
```

```rust
pub const REQUIRED_SCHEMA_VERSION: i64 = 11; // core 7.1.3 CURRENT_SCHEMA_VERSION (migrations.ts)

pub fn validate_schema(tx: &rusqlite::Transaction, prefix: &str) -> Result<(), GraphragError> {
    let version: Result<Option<i64>, _> = tx
        .query_row(&format!("SELECT value FROM {prefix}meta WHERE key = 'schema_version'"), [], |r| {
            r.get::<_, String>(0).map(|s| s.parse::<i64>().ok())
        })
        .map(Some)
        .or_else(|e| match e { rusqlite::Error::QueryReturnedNoRows => Ok(None), other => Err(other) });
    match version {
        Ok(Some(Some(v))) if v == REQUIRED_SCHEMA_VERSION => Ok(()),
        Ok(_) => Err(GraphragError::SchemaMismatch(format!(
            "expected {prefix}meta.schema_version = {REQUIRED_SCHEMA_VERSION}"))),
        Err(e) => Err(GraphragError::SchemaMismatch(format!("marker unreadable: {e}"))),
    }
    // plus PRAGMA table_info checks for required columns of {prefix}entries and {prefix}edges
}
```

### Task 7: Traversal engine — BFS walk, gates, ordering, cap (REQ-SLICE-01)

**Files:**
- Create: `crates/graphrag-core/src/traversal.rs`
- Test: `crates/graphrag-core/tests/fixtures_tests.rs` (parity + robustness fixtures for the walk stage)

**Interfaces:**
- Consumes: `ResolvedInputs`, prefix, `Transaction`.
- Produces: `walk(tx, prefix, entity_id, source_id, inputs) -> Result<Vec<SelectedNode>, GraphragError>` with `SelectedNode { id: String, depth: i64, updated_at: i64 }` in final order (anchor first), already capped.

- [ ] **Step 1: Anchor resolution** — `SELECT id, updated_at FROM {prefix}entries WHERE id = ? AND entity_id = ? AND deleted_at IS NULL`; no row → `Ok(vec![])`. Anchor bypasses gates. Cycle-safe visited set: `HashSet<String>` of opaque IDs (delimiter-defect correction).
- [ ] **Step 2: BFS layers** — expand frontier while its depth `k − 1 < d` (real-valued compare, unrounded). Neighbor candidate query per frontier node (batched per layer within variable limits — bind frontier IDs in bounded groups ≤ 500, OR-loop per group preserving union):

```sql
SELECT e.source_id, e.target_id, n.id AS node_id, n.updated_at,
       CASE n.confidence WHEN 'tentative' THEN 0 WHEN 'inferred' THEN 1 WHEN 'certain' THEN 2 ELSE -1 END AS rank,
       n.source_type
  FROM {prefix}edges e
  JOIN {prefix}entries n
    ON n.id = (CASE WHEN e.source_id = ? THEN e.target_id ELSE e.source_id END)
   AND n.entity_id = ? AND n.deleted_at IS NULL
 WHERE e.entity_id = ?
   AND ((? != 'inbound'  AND e.source_id = ?) OR (? != 'outbound' AND e.target_id = ?))
   AND ({edge_type_group_clause})            -- '1=1' when no filter; IN-groups when Some(list)
```
